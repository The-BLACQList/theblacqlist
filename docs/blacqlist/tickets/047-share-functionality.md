## Context

Every BLACQList Page needs a shareable link that renders a rich OG preview when shared on social media. The share interaction is a `ShareButton` Client Component that adapts to the user's device: on mobile browsers that support the Web Share API (`navigator.share`), it opens the native OS share sheet with the listing name, a short description, and the URL. On desktop or unsupported browsers, it copies the URL to the clipboard and shows a confirmation toast.

The OG metadata for each listing is generated by Ticket 023 (the `generateMetadata` function on the listing page). The `ShareButton` reads the listing name and current URL from its props — it does not re-fetch metadata.

The share interaction fires a `listing_shared` analytics event as a fire-and-forget POST to `POST /api/analytics/event`. This must never block the UI.

Sources: `docs/blacqlist/ux/mvp-screen-map.md` § Business BLACQList Page (Save/Share buttons); `docs/blacqlist/architecture/api-contract.md` § 17 (Log Analytics Event); `docs/blacqlist/ux/empty-loading-error-success-states.md` § Global States (Copy link success toast).

---

## User Story

As a visitor or supporter on a BLACQList Page, I want to share the listing with one tap using my phone's native share sheet (or copy the link on desktop), so that I can send it to friends or post it without manual URL copying.

## Scope

**In scope:**
- `components/listing/ShareButton.tsx` — "use client"; self-contained share button
- Props: `{ listingName: string, listingUrl: string, className?: string }`
- Behavior decision tree:
  1. If `navigator.share` is available: call `navigator.share({ title: listingName, text: "[listingName] — Found on The BLACQList", url: listingUrl })`; handle `AbortError` silently (user dismissed the sheet); handle other errors with a fallback to clipboard copy
  2. If `navigator.share` is not available: call `navigator.clipboard.writeText(listingUrl)`; show toast "Link copied!"
- Analytics event: `listing_shared` — fire-and-forget `POST /api/analytics/event` after a successful share (not on AbortError)
- Toast: "Link copied!" — 2 seconds — for clipboard path (from `empty-loading-error-success-states.md` § Global States)
- No toast needed for Web Share path (native OS confirmation is sufficient)
- Used on: BLACQList Page quick-actions bar (icon + "Share" label); listing cards (icon-only, optional — see scope note below)
- On listing cards: share button is not required at MVP on cards — only required on the BLACQList Page; include an `iconOnly` boolean prop so it can be added to cards later without a new component

**Out of scope:**
- Custom OG image generation (Ticket 023)
- Twitter/X card metadata (part of Ticket 023's `generateMetadata`)
- Social media deep-linking (direct share to Instagram, etc.) — post-MVP
- Share count tracking or display

## UX Notes

- **Screen:** BLACQList Page quick-actions bar — `docs/blacqlist/ux/mvp-screen-map.md` § Business BLACQList Page
- **Route:** Used on `/[city-slug]/business/[listing-slug]`
- **Entry points:** Quick-actions bar on the BLACQList Page (desktop and mobile); hero area on mobile
- **Exit points:** Native share sheet (mobile) or clipboard copy toast — no navigation
- **Mobile behavior:** Web Share API is available on iOS Safari 12.1+ and Android Chrome 61+; this covers the vast majority of real-world mobile users; desktop Chrome 89+ also supports it but with fewer system integrations. The fallback clipboard path handles all other cases gracefully.
- **Clipboard fallback on HTTPS only:** `navigator.clipboard.writeText` only works over HTTPS. In local development (`localhost`), it works. On any HTTP deployment, fall back to a `document.execCommand('copy')` polyfill or show a "Copy this link:" text with the URL pre-selected.

**Toast (from `empty-loading-error-success-states.md` § Global States):**
- "Link copied!" — 2 seconds, no dismiss button

**AbortError handling:** When the user opens the native share sheet and then taps "Cancel" or "Dismiss", `navigator.share()` rejects with an `AbortError`. This is expected behavior — not a failure. Do not show an error toast. Do not fire the analytics event.

## Implementation Notes

**Files to create:**
- `components/listing/ShareButton.tsx` — "use client"; self-contained

**Files to modify:**
- `app/[city-slug]/business/[listing-slug]/page.tsx` or the quick-actions bar component — import and render `<ShareButton listingName={listing.name} listingUrl={canonicalUrl} />`

**Key implementation:**

```typescript
"use client"

import { ShareIcon } from 'lucide-react'
import { Button } from '@/components/ui/button'
import { toast } from 'sonner'  // or whichever toast library is in use

interface ShareButtonProps {
  listingName: string
  listingUrl: string
  listingId?: string   // for analytics event; optional
  iconOnly?: boolean
  className?: string
}

export function ShareButton({ listingName, listingUrl, listingId, iconOnly, className }: ShareButtonProps) {
  async function handleShare() {
    const shareText = `${listingName} — Found on The BLACQList`
    
    if (typeof navigator !== 'undefined' && navigator.share) {
      try {
        await navigator.share({ title: listingName, text: shareText, url: listingUrl })
        // Only fire analytics if user didn't cancel
        fireAnalytics('web_share_api')
      } catch (err: unknown) {
        if (err instanceof Error && err.name === 'AbortError') return // user cancelled — silent
        // Fall through to clipboard
        await copyToClipboard()
      }
    } else {
      await copyToClipboard()
    }
  }

  async function copyToClipboard() {
    try {
      await navigator.clipboard.writeText(listingUrl)
      toast("Link copied!", { duration: 2000 })
      fireAnalytics('clipboard')
    } catch {
      toast.error("Couldn't copy link. Try selecting the URL manually.")
    }
  }

  function fireAnalytics(method: 'web_share_api' | 'clipboard') {
    try {
      fetch('/api/analytics/event', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          event_name: 'listing_shared',
          entity_id: listingId ?? null,
          properties: { share_method: method }
        })
      })
      // intentionally not awaited
    } catch { /* swallow */ }
  }

  return (
    <Button
      variant="ghost"
      onClick={handleShare}
      aria-label={`Share ${listingName}`}
      className={className}
    >
      <ShareIcon className="h-5 w-5" aria-hidden="true" />
      {!iconOnly && <span className="ml-2">Share</span>}
    </Button>
  )
}
```

- SSR safety: `typeof navigator !== 'undefined'` check ensures no build-time errors from `navigator.share`
- The `listingUrl` prop should be the full canonical URL: `https://theblacqlist.com/[city-slug]/business/[listing-slug]`; the listing page passes this via `process.env.NEXT_PUBLIC_SITE_URL + pathname`

**Do not:**
- Show an error toast on `AbortError` — the user deliberately cancelled
- Await the analytics fetch — it must be fire-and-forget
- Add any new npm packages for this feature — `navigator.share` and `navigator.clipboard` are native browser APIs

## Acceptance Criteria

- [ ] Given a mobile user taps "Share" on a BLACQList Page and their browser supports the Web Share API, then the native OS share sheet opens with the listing name, short description, and URL pre-filled
- [ ] Given the user dismisses the share sheet without sharing, then no toast appears and no analytics event is fired
- [ ] Given a desktop user clicks "Share" (Web Share not available), then the listing URL is copied to the clipboard and a "Link copied!" toast appears for 2 seconds
- [ ] Given clipboard write fails (e.g., HTTPS not available), then a toast shows: "Couldn't copy link. Try selecting the URL manually."
- [ ] Given any successful share action (Web Share or clipboard), then a `listing_shared` analytics event is fired fire-and-forget — it does not block the UI
- [ ] The button renders with icon + "Share" label on the BLACQList Page quick-actions bar; renders icon-only when `iconOnly={true}`
- [ ] `aria-label="Share [Business Name]"` is present on the button in all modes
- [ ] Mobile at 375px: button tap target is at least 44×44px; share sheet opens on tap

## Failure States

| Failure | Condition | User sees | Recovery |
|---|---|---|---|
| Web Share API rejects (non-AbortError) | Unexpected browser error | Falls back to clipboard; "Link copied!" if successful | Clipboard fallback is transparent |
| Clipboard write fails | HTTP page, browser permissions denied | Toast: "Couldn't copy link. Try selecting the URL manually." | User manually copies |
| Analytics event fails | Network error on analytics POST | Nothing — swallowed silently; user unaffected | N/A |

---

## Edge Cases

- `navigator.share` is available but the device's share targets do not include a messaging app — the native sheet still opens with available options; this is a system behavior, not an app problem
- `listingUrl` contains special characters (e.g., accented characters in a city name) — the URL should already be percent-encoded; `navigator.share` and clipboard copy both handle encoded URLs correctly
- User taps Share twice quickly — second click while the share sheet is open may throw; wrap in a loading guard (`isSharing` boolean state) to debounce
